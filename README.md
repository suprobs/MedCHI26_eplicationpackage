# From User Manuals to Mixed-Reality Simulations: replication package

This package accompanies the paper *From User Manuals to Mixed-Reality Simulations: A Conceptual Model and an AI-supported Authoring Tool* (under double-blind review). It contains the authoring tool, the prompts, the three model instances of the case study, the schemas of the instance files, the validator used to check them, and the Unity runtime scripts that execute them on Meta Quest 3.

## 1. Authoring a model instance

1. Open `tool/index.html` in the browser.
2. Load the PDF manual of the device.
3. Follow the three phases: information extraction, behaviour modelling and 3D representation modelling.

The tool does not call an LLM itself. In each phase it generates a prompt, which the author pastes into an LLM chat (Claude Opus 5.5 in the study). The author then loads the response back into the tool for review. `prompts/` contains the prompts as they were generated during the study.

The tool checks integrity constraints C1–C4 each time the behavioural specification is generated. It checks C5 and the bindings between the two files when exporting.

Because LLM output is not deterministic, running the prompts again will produce drafts that differ from the published instances. The published instances are the ones that were evaluated.

## 2. Validating an instance

```bash
pip install -r validation/requirements.txt
python validation/validate_instance.py \
    --efsm  instances/coffee_preparation/efsm_coffee_preparation.json \
    --spec  instances/coffee_preparation/device_spec_coffee_preparation.json \
    --json  instances/coffee_preparation/validation_report.json
```

The validator runs three groups of checks:

- **Schema.** It validates the structure of both files against `schemas/`.
- **Integrity constraints C1–C5 (Section 3.2).** It checks the references between elements. It then runs a simulated walk of the target procedures from the initial values, in order, and checks that every step can fire and that the postconditions hold at the end. These checks, and whether each one is reported as an error or a warning, mirror those of the authoring tool.
- **Competency questions CQ1–CQ14 (Table 1).** It answers each question by querying the instance. Questions about elements that the instance does not contain are reported as n/a. See `validation/cq_mapping.md`.

Running the validator on the three instances reproduces the competency-question results of Tables 1 and 2. The exit code is 0 when there are no errors.

## 3. Running the simulation

1. Create a Unity 2022.3 LTS project with the Meta XR SDK 201.0.0 and copy `unity/Assets/Scripts/EFSM/` into `Assets/`.
2. Place the two JSON files of an instance in the project. Assign the behavioural specification to `EfsmJsonLoader.jsonFile` and the device specification to `GenericDeviceBuilder.deviceSpecJson`.
3. In edit mode, run *Build From Device Spec* from the context menu of `GenericDeviceBuilder`. It generates the device hierarchy under an unscaled `DeviceRoot`, using primitive geometry. It also adds the binders, movement sensors, press triggers and highlight components.
4. Run *Generate Inspector Checklist* from the same menu. Then complete the grab setup of each interactive component in the Inspector (`Grabbable`, transformer, `HandGrabInteractable`), following the checklist.
5. Save the scene. Running the builder again deletes the hierarchy and the manual setup.
6. Build for Android and run on Meta Quest 3. `EfsmKeyboardTestDriver` lets you step through a procedure in the Editor without a headset.

Main runtime scripts:

| Script | Role |
|---|---|
| `EfsmJsonLoader` | Loads the behavioural specification |
| `EfsmStateManager` | Runs the procedure: steps, guards, events |
| `EfsmComponentBinder` | Links a scene object to its state machine |
| `ConstrainedMover` | Converts the progress of a grab movement into actions |
| `EfsmPressTrigger` | Press interactions |
| `EfsmStickToTarget` | Attach interactions |
| `GenericDeviceBuilder`, `DeviceSpec` | Builds the scene from the device specification |
| `ProcedureUIController`, `ITSGuideController`, `EfsmHighlightPulse` | Step instructions, guidance and highlighting |
| `SessionLogAnalyzer` | Session metrics from the exported logs |

Meshes are not included. Components are represented by primitives, which can be replaced through `representation.mesh_override`.
